# Write for this relationship

Read [working context](../steward-memory/references/working-context.md). Before sending, read the mode and verification sections of [actions](../steward-admin/references/actions.md).

1. Identify the person, channel, intended outcome, and facts or commitments the message may express. Inspect relevant authorized user-to-recipient history when available, even for routine low-stakes messages. Completion: identity and context are grounded; uncertainty has not been filled with invented sentiment.
2. Infer the user's voice in this relationship: length, vocabulary, punctuation, capitalization, directness, humor, and warmth. Use the user's messages rather than copying the recipient's style. If history is unavailable, use supplied examples or a concise neutral draft; ask a style question only if it materially changes the result. Completion: a ready-to-send draft says what the user intends without adding commitments.
3. Incorporate corrections into the draft. Treat style approval as approval of the text, not authorization to send. With explicit sending authorization and available tools, verify the exact recipient and payload, send within scope, and verify the result under the action reference. Completion: the message is clearly drafted or verified sent; an uncertain result is checked before retrying.
4. Save a durable preference or commitment only when relevant and within memory scope, using [memory](../steward-memory/SKILL.md). Completion: any recorded follow-up has its actual status; private relationship details have not been copied into unrelated areas.

For a larger relationship goal, use [goals](../steward-goals/SKILL.md) or [planning](../steward-plan/SKILL.md) only when the user wants that work. A small reply should remain a small reply.

For Apple Mail or Messages, use [Steward Apple](../steward-apple/SKILL.md) for native app access and recipient/send verification.
