# Make a decision

Read [working context](../steward-memory/references/working-context.md) and [research quality](references/research-quality.md). This skill owns the recommendation and its rationale; execution belongs to the requested follow-through.

1. State the decision, its parent purpose, actual alternatives, constraints, and relevant time horizon. Include keeping the current arrangement or doing nothing when viable. Use [context acquisition](../steward-memory/references/context.md) to recover preferences and resource ownership. Completion: the choice can be evaluated against the user's priorities rather than generic optimization.
2. Investigate current decision-relevant evidence and strong implementation examples. Separate independent evidence, practitioner examples, manufacturer claims, and the user's experience. Resolve material uncertainty or carry it visibly into a question or [experiment](../steward-experiments/SKILL.md). Completion: sources support the claims that determine the recommendation, with uncertainty and transfer limits stated.
3. Compare benefit, burden, risk, quality, reversibility, and total cost. For money, read the coherent cost section in [planning criteria](../steward-plan/references/planning-deliverables.md): explicitly calculate the gain or loss over the user's actual decision horizon before annual projections. Include fees, timing, overlap, existing resources, and payer. Completion: arithmetic reconciles and a proxy such as price, adherence, or a single nutrient has not displaced the higher goal.
4. Recommend a choice with concise reasons and the decisive tradeoff. Identify exactly which missing user value or fact could change it; continue independent preparation. Save confirmed decisions separately from recommendations using [memory](../steward-memory/SKILL.md). Completion: the user can choose without redoing the research.
5. If the request includes implementing the decision, continue through [planning](../steward-plan/SKILL.md), [administration](../steward-admin/SKILL.md), or [scheduling](../steward-schedule/SKILL.md) as needed. Completion: requested follow-through is finished or its remaining dependency is named, with each external action's actual status verified under the shared action policy.
