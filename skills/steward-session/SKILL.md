# Check in → Make progress → Adjust

Read [working context](../steward-memory/references/working-context.md). This entry owns the session experience, not the specialist work. The user can name a request, report a change, or simply ask what comes next. Keep this one conversation: select and read the supporting skills yourself, then carry out their work. Explain the useful next move in ordinary language; expose skill names when the user asks for the map or explicitly selects one. Changing work owners does not require the user to invoke another skill.

During guided setup or onboarding, ask the smallest question that unlocks useful progress, acknowledge the answer, and build on it before asking more. Reuse supplied preferences. Bundle only closely related choices when doing so is easier for the user. A clear direct request starts the work without an orientation interview.

1. **Check in.** Recover relevant context through [memory](../steward-memory/SKILL.md), including any saved [session state](references/session-state.md). Distinguish technical readiness from personal onboarding. If setup is requested or missing access blocks the task, use [setup](references/setup.md); for app connection choices, interrupted permissions, or access changes, use [connections](references/connections.md); for requested first-use orientation or resumed onboarding, use [onboarding](references/onboarding.md). A specific request proceeds directly even when optional onboarding is unfinished. For an open check-in, recommend the next useful step from current commitments; ask only when missing facts or competing priorities change that choice. Completion: one useful direction or one precise pending choice, with known context reused.
2. **Make progress.** Select the work owner below and read its instructions. Complete the requested work in this task, loading other specialists only for actual dependencies. Before choosing a materially new approach or producing an important deliverable, use the exemplar checkpoint in [research quality](../steward-decide/references/research-quality.md). Completion: a usable result or a specific unresolved dependency; planning physical activity is recorded as preparation, not participation.
3. **Adjust.** Verify actual outcomes and save material changes through memory. When durable state changed, update the existing home/session view with the current focus, next action, pending decisions, and relevant review trigger; follow [session state](references/session-state.md). A short read-only answer needs no bookkeeping. Completion: explain the result and next step plainly; future work can resume from saved state without the original conversation.

The loop can span sessions. On return after a gap, check what remains relevant and what actually happened before carrying work forward. Missing observations stay unknown. A small request can finish in one response without a questionnaire or new goal. Scheduled check-ins are an optional, explicitly requested [scheduling](../steward-schedule/SKILL.md) task; otherwise return happens when the user next interacts.

| Complete a chosen administrative action | [admin](../steward-admin/SKILL.md) |
| Draft or send personal correspondence | [messages](../steward-messages/SKILL.md) |
| Learn from actual progress or friction | [review](../steward-review/SKILL.md) |
| Test a specific uncertainty | [experiments](../steward-experiments/SKILL.md) |

Invoke this entry for the product's guided experience, not every use of “continue” in unrelated work. Specific specialist requests keep their direct route.
