# Your first useful session

Personal onboarding is separate from installing skills and connecting memory. Recover what is already known; a specific request can proceed immediately. First use is not a questionnaire about every part of the user's life.

Start from the user's words. If they have no request yet, a useful opening is “What would you like to make a little easier right now?” Follow their answer, using examples only when they need help choosing. Weave unresolved memory and app choices into that conversation, explaining each choice when it matters. The branches below describe what must be resolved, not a script to recite in order. Offer optional connections before marking onboarding complete, but keep a useful request moving while optional setup is pending. Never ask the user to select a specialist just to continue the conversation.

1. **Choose what Steward can use.** Reuse the selected memory folder. If app choices are unresolved, offer [connections](connections.md) early: Calendar, Reminders, Notes, Contacts, Mail, and Messages on a supported Mac, or available host equivalents. Record selections/skips and verify selected routes. Explain context use and private-write defaults. If permissions are pending, finish independent work and keep the exact next step. Completion: choices are saved; each selected source has honest access state or an explicit deferral.
2. **Find a starting point.** Use the user's existing request. Otherwise use [focus](../../steward-focus/SKILL.md) and the optional [area menu](life-areas.md) to choose what deserves attention now. Completion: one user-chosen direction; suggestions remain proposals until chosen.
3. **Make something useful.** For an ongoing outcome, recover or define success and constraints with [goals](../../steward-goals/SKILL.md). For a small request, go directly to its work owner. Retrieve decision-relevant context from selected sources using [connected context](../../steward-memory/references/connected-context.md). Deliver the smallest useful result and finish authorized implementation. Completion: an actual usable result, with preparation distinguished from real-world participation.
4. **Leave a return point.** Save through [memory](../../steward-memory/SKILL.md), preserving [session state](session-state.md). State the current focus and next step, then explain: “Bring a request, tell me what changed, or ask what’s next.” Create follow-ups only when requested through schedule. Completion: first result, connection choices, and next step are retrievable; no-storage users receive a portable continuation note.

Save the last completed step and smallest pending question when interrupted. Respect skipped onboarding and skipped apps. Adding a goal or starting a fresh conversation does not restart setup. Revisit life areas and labels when useful to the user.
