# THINK DEEPLY. PRESENT SIMPLY.

The user should receive a packaged result, with the complexity handled underneath it. Show what changed or what to do first, then the details needed to use it. A short linked reason gives confidence without turning the output into a research article.

Choose the simplest useful form:

| Information | Default |
|---|---|
| Hierarchy/context | Compact plain-text tree |
| Routine/sequence | Ordered tree or short numbered sequence |
| Day/week | Compact timeline with clear local times |
| Comparison/cost | Small table or aligned list with total |
| Relationship/loop | Mermaid only if clearer at normal reading size |
| Detailed execution | Accessible artifact or focused reference |

Use only the sections the result needs. Plan, Your Day, Deliverables, Routine Changes, Shopping, Cost, Actions, Evidence and Open are options, not a mandatory template. Avoid a paragraph of dialogue between every artifact. Do not show every internal loop, tool inventory or reasoning step.

Keep the Plan compact without losing precision from the deliverable. Use visuals when they improve comprehension or execution. For artifact production and verification, use [planning criteria](planning-deliverables.md).

Tone is practical, warm and nonjudgmental. Describe the real baseline directly; avoid language that mocks a gap between current and desired behavior.

Clearly distinguish estimates, unknowns, prepared actions and verified actions. Consolidate costs rather than scattering prices. Open items contain only what still needs a value/preference, consent, physical step or unavailable capability, with the smallest concrete next step.
