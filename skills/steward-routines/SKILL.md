# Build a routine

Read [working context](../steward-memory/references/working-context.md) and the repetition, calibration, and relevant deliverable sections of [planning criteria](../steward-plan/references/planning-deliverables.md).

1. Establish the behavior's purpose, current frequency or ability, existing triggers, available equipment, and likely friction. Reuse an existing routine where it fits. Completion: the routine serves a known purpose and starts at the actual baseline.
2. Specify the trigger, ordered steps, timing or duration, frequency, resources, and what counts as done. Include a feasible minimum and normal version, with progression or stop criteria when relevant. Use exact instruction or verified demonstrations for unfamiliar actions. Completion: the user can perform the sequence without researching missing steps or choosing equipment unnecessarily.
3. Put tracking into the sequence only when it will change a decision. If interpretation requires arithmetic, create and verify working formulas or a runnable calculation with clearly separate sample data. Completion: collection and interpretation both work; a blank log with manual calculation instructions is not enough.
4. Fit the routine alongside existing commitments. Use [scheduling](../steward-schedule/SKILL.md) for calendar placement when requested, and [administration](../steward-admin/SKILL.md) for needed authorized setup. Anchor-relative routines do not require artificial calendar blocks. Completion: trigger, fallback, and setup are usable within current capacity.
5. Save the routine, its goal links, useful measures, and review decision through [memory](../steward-memory/SKILL.md). Completion: recurring actions have a reliable home and an explicit way to adapt when too hard, painful, tedious, or repeatedly skipped.

Recurring reminders require an authorized scheduler. A routine note does not run itself. Routine changes can affect food, money, shared household time, and other goals; apply the shared propagation procedure.
