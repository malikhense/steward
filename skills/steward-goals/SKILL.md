# Manage goals

Read [working context](../steward-memory/references/working-context.md) and [the model](../steward-memory/references/model.md). This skill owns the outcome and its lifecycle. A plan explains how to reach it.

1. Identify the intended goal by its meaning and existing identifier. Retrieve the current record before creating another. A second goal gets its own record; it does not replace the current focus or another goal by default. Completion: the target goal is unambiguous, or only the ambiguous choice remains pending.
2. Define the outcome, why it matters, baseline, practical success signal, constraints, dependencies, and a review point. Use dates only when meaningful; maintaining a condition can be a valid goal. Keep strategies revisable and user values distinct. Completion: success is recognizable without inventing metrics or a deadline the user did not want.
3. Apply the requested transition: proposed, active, paused, completed, or retired. For resumption, check stale constraints and the last unresolved work. Completion needs evidence against the success signal, not just a finished checklist. Retiring or pausing a goal requires inspecting known related commitments; use [actions](../steward-admin/references/actions.md) for their actual state and any authorized changes. Completion: goal status and affected commitments agree, with any pending live changes explicitly recorded.
4. Save the distinct goal and relevant links using [memory](../steward-memory/SKILL.md). Continue into [planning](../steward-plan/SKILL.md) when the user requested a path or implementation. Completion: a durable goal record or portable continuation note, clear next work, and no accidental change to other goals.

Goal status and action mode are separate. An active goal can still have a prototype plan; setting a goal does not authorize purchases, sends, or calendar writes. When shared constraints change, follow the propagation procedure in working context.
