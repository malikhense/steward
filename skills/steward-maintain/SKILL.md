# Maintain the memory system

Read [working context](../steward-memory/references/working-context.md) and [storage](../steward-memory/references/storage.md). This skill owns vault integrity; personal progress reviews belong to steward-review.

1. **Scope.** Identify the requested operation, exact vault, trusted configuration, existing organization, human-owned notes, recovery arrangements, and available file/Obsidian capabilities. Completion: one bounded target and operation, with required access or location choices resolved.
2. **Prepare.** Use only the applicable branches below. Completion: every intended change has a target and verification criterion; unresolved facts remain explicit.
3. **Apply and verify.** For authorized mutations, follow storage's write procedure and the selected branch's checks. An audit can end with findings alone. Completion: every scoped change is verified or recorded as pending with its reason; human edits and indexes are consistent with the result.
4. **Report.** Record changes, checks, unresolved work, and setup prerequisites without copying forgotten content. Completion: the next task can recover the maintenance result and its limits.

## Operation branches

- **Setup or migration:** Choose the smallest compatible structure from storage, preserving existing conventions. Prepare a compact index and trusted instructions pointing to the canonical vault. For migration, map old to new locations with provenance and human content intact. Use storage's app-aware move procedure where applicable. Verify accessible records, links, and index after applying. Check fresh-session lookup, distinct goal identity, correction supersession, and proposal versus live state; keep synthetic fixtures outside personal records and report checks that could not run.
- **Audit or repair:** Inspect the requested scope for stale claims, contradictions, orphaned records, broken links, duplicates, and outdated derived indexes. Separate mechanical repairs from factual disagreements; retain healthy prose. Every discovered issue needs a verified repair, a finding when only auditing, or a precise unresolved reason.
- **Forgetting:** Trace the requested information through sources, current notes, synthesis, history, caches, indexes, and accessible recovery surfaces. Apply scoped removal under the host's deletion rules without preserving the forgotten content in a new audit note or recovery copy. Verify absence from active retrieval surfaces. Identify residual version history, backups, synced copies, or external systems and the remaining action for each. Report verified coverage; never claim secure erasure without evidence.
- **Retrieval improvement:** Establish known-answer questions and measure current index, link, and text-search results before changing retrieval. Add a rebuildable semantic index only when observed misses justify it and setup is authorized. Compare the same questions afterward, including regressions and unresolved misses; Markdown remains authoritative.

Recurring maintenance uses steward-schedule only when requested. Application updates and CLI registration are explicit setup work; ordinary note edits use the available capabilities described in storage.
